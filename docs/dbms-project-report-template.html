3. Abstract

Nidaan is a clinic consultation and adverse drug event detection platform. It stores patients, appointments, consultations, prescriptions, drugs, interactions, invoices and safety reports in PostgreSQL. Database constraints preserve integrity, transactions protect concurrent booking and billing, and triggers automatically create interaction alerts and reminders. Adverse-event narratives are embedded with a 384-dimensional language model vector and searched with pgvector, allowing semantically similar reports to be retrieved even when patients use different words. The system supports receptionist, prescriber, pharmacovigilance and administrator roles through a Next.js interface and server-side authorization.

5. SQL — Database Commands

5.1 Schema and tables

The schema begins by enabling pgvector and creates the relational tables: user_account, doctor, patient, appointment, consultation, drug, prescription, prescription_item, drug_interaction, interaction_alert, ade_report, invoice, invoice_line, reminder_queue, audit_log and patient_allergy.

CREATE EXTENSION IF NOT EXISTS vector; psql -d nidaan -f db/01_schema.sql psql -d nidaan -f db/02_triggers.sql psql -d nidaan -f db/03_procedures.sql psql -d nidaan -f db/04_views.sql psql -d nidaan -f db/05_seed.sql

5.2 Constraints and integrity

  • Primary keys identify every row; foreign keys connect the clinical chain.
  • Role, appointment mode, status, positive quantity and non-negative price use CHECK constraints.
  • Online appointments require a meeting link; in-person appointments cannot have one.
  • drug_a_id < drug_b_id prevents reverse duplicate interaction pairs.
  • ON DELETE RESTRICT protects historical clinical data.

6. NoSQL / Vector Database Commands

Nidaan uses PostgreSQL with the pgvector extension rather than a separate NoSQL server. The vector component is appropriate for free-text narratives, while the relational component preserves clinical integrity.

6.1 Embedding generation

npm run embed:seed

This embeds every adverse-event report whose narrative_vec is null. The model returns a normalized 384-dimensional vector.

6.2 Full-text baseline

SELECT report_id, narrative FROM ade_report WHERE narrative_tsv @@ plainto_tsquery('english', 'bleeding gums');

6.3 Vector similarity

SELECT report_id, narrative, 1 - (narrative_vec <=> $1) AS similarity FROM ade_report WHERE narrative_vec IS NOT NULL ORDER BY narrative_vec <=> $1 LIMIT 5;

The vector query can retrieve semantically similar wording such as “blood while brushing teeth, unusual bruising” for a report mentioning “bleeding gums and purple patches on arms”.

Conclusion

Nidaan combines relational correctness with vector-based semantic discovery. PostgreSQL protects the clinical workflow, triggers and functions automate database behaviour, and pgvector helps the pharmacovigilance role discover adverse-event patterns beyond exact keyword matching.
